# Medieval Town Defense — project handoff

A medieval village-builder + tower-defence browser game prototype (inspired by Kingdom Rush and Age of Empires). Owner: Jack. He tests mostly on his phone (portrait and landscape) and also on desktop.

The whole game is currently one self-contained file: `index.html` (~165 KB, three.js r128 from cdnjs). It was built over ~37 iterations in a claude.ai chat and published as an artifact; this repo continues it in Claude Code.

## How to run
- Open `index.html` in a browser, or serve the folder: `npx serve .` / `python3 -m http.server`.
- To test on a phone: serve on the LAN, or enable GitHub Pages on the repo.
- Live build: https://jacktan98.github.io/Medieval-Town-Defense/ (GitHub Pages from `main` root; push to `main` to deploy).
- First real-WebGL playtest done 2026-10-27 (desktop, phone portrait/landscape): all building tiers, villager tools/poses, night waves, end screen render correctly.
- Debug: open `index.html?debug` and `window.G('code')` evaluates inside the game closure (e.g. `G('res.gold=9999')`, `G('PH.t=0')` to skip the day).
- Design gallery: Admin → Gallery, or open `index.html?gallery` (live: https://jacktan98.github.io/Medieval-Town-Defense/?gallery). Its own scene (`gScene`, the game paused underneath; Back restores it): rows of every building at tiers 1–3 (`GAL_X` columns), walls running into a gate, decor, villagers working/carrying, soldiers by tier and raiders attacking, animated with the game's own poses (`TOOL_POSE`, `bowPose`, `makeRaider`, `addLoads`). Bar: Turn (all buildings a quarter turn; tapping one turns just it), Doors, Walk. `gRows` lists rows for the render script.
- Before every push: `node tools/check.js` (syntax check of the inline game script; a single syntax error stops the whole game loading on the live site).
- Render checks: `node tools/render/gallery.js --back` writes `design/gallery/sheet.png` / `sheet-back.png` (run after art changes and commit them); `node tools/render/motion.js` counts villager shaking and checks sites get built. In the cloud, cdnjs is blocked: pass `--three` a local three r128 (`npm pack three@0.128.0`). See `tools/render/README.md`.

## Style rules (from Jack)
- UI text is minimal: a few words, no explanations (hints like "Pick a spot", "Occupied", "Need [wood]5"; banners "Night 2 · 8 raiders"; log lines "<b>Cottage</b> ready"). Keep new text in this style.
- Colour code: town = blue (flags, soldiers, tier-3 roofs), raiders = red, villagers = yellows. Roofs by tier: tier 1 straw thatch (`M.thatchOld`: strands radiate from the peak by object-space angle, level course lines by world y), tier 2 compact rounded logs from ridge to eave like the palisade (`logRoof`: `M.thatch` for pyramids: staggered wooden shingles (rows by world height); `M.logGable` for gable slabs by local x; each has its own `customProgramCacheKey`), tier 3 blue tiles (`M.roofBlue`, `roofGrit`). Every roof has a thick eave: `pyramid()` and `coneRoof()` (blue tower cones) return a group with the roof plus a band under its edge; gable slabs are 0.1 m thick. Bases by tier: tier 1 house, lumber camp, quarry, castle, barracks and archer tower stand on a packed-earth slab (`M.court` with the `earth` grit: mottled packed earth with dark and pale pebble specks, like the palisade fort's yard; `SLAB`, top `SLAB_TOP` .08, added in `makeModel`) that fills the footprint, so the fort's palisade sits on it and neighbours join up; tier 2 bases are plain grey stone (`M.plainStone`, rock grit, no block joints); tier 3 bases keep the masonry `M.stone`. `plinthTop(type, tier)` gives the top height for `snapToNeighbours` (placement, within 0.8 m) and `stoneAt` (paths stop at any base's edge); Bases (footprint-wide meshes below ground level) take one shade per tier in `makeModel`'s tinting, so neighbours match. `planFlatten` may lower ground on an edge shared with a locked neighbour down to the new building's level (never raise it), so no base gets buried; the T1 slab is 1 m deep. `flushHeight` finds the matching height, and `settleBase` re-levels a building after each upgrade so its new base stays flush with neighbours whatever their tier (only within 0.3 m; much higher or lower ground is left alone). Tier 1 farms have no base.
- Medieval look over clean/modern: crooked timbers, daub, thatch, small shuttered windows.

## Recent model notes
- Phones: the long loops load a compressed `.m4a` copy first (`afconvert -f m4af -d aac -b 96000 x.mp3 x.m4a`), falling back to the `.mp3`; regenerate the copy when a loop is replaced. Night/bird loops don't preload. The top panel has no backdrop blur, and fog follows zoom and sits well back (`near = dist + 100`, `far = dist + 240`; Jack found the old dist + 35/130 made the top of a portrait screen look blurry) so the top of a portrait screen stays crisp. The renderer runs at the full `devicePixelRatio` (up to 3; it used to be capped at 2, which looked soft on an iPhone); `adaptResolution` (in `frame`) averages frame time every 3 s and drops `pixelK` by 0.5 (floor 1.5) while frames average over 24 ms.
- `separateUnits` (after unit updates each frame) pushes villagers and live raiders apart (radius .24/.26, horse .55); fallen raiders are fixed obstacles; no push into unwalkable ground.
- Juice: `shake(amp, at)` (building hit .07, destroyed .35; fades with distance from the camera focus, applied around render only), `debrisBurst` + `updateDebris` on raid destruction, raiders flash (`hitFlashM`, `flashT`) when hit, puff dust as they fall (`hurtEnemy`) and sink away by 1.9 s; health bars (raiders, soldiers, buildings) show only once damaged, finished/upgraded buildings bounce in x/z (`B.pop`) with a dust ring, `coinFly` sends DOM coins from on-screen gold payouts to `#cGold` (pulse), villagers cheer (hop, arms up) for 2.6 s at dawn (`cheerT`). `Wave_horn.mp3` plays at nightfall (`SND.horn`).
- Guided first day (`GUIDE`, `guideTick` from the HUD tick, `guideMark` adds `.guidePulse` to the tab/tool to press): house → lumber camp → farm → archer tower → upgrade; steps tick off by game state, Skip button; once done/skipped `localStorage['mtd-guide']='done'`.
- Walls connect only to walls and gates (`WALLY`), never to towers or the castle.
- Ground shadows: `syncTerrain` must call `tGeo.computeVertexNormals()`; r128's shadow lookup reads the normal even with no normal bias, and without normals the terrain received no shadows at all.
- Grit: `addGrit(material, 'wood'|'stone'|'rock')` adds world-space noise (wood grain, stone mottling, rock specks) on top of any existing shader, with its own `customProgramCacheKey` (needed: three keys programs by onBeforeCompile source, identical for every grit kind); `tinted` copies the key.
- Units are drawn at `UNIT_K` (.78) so they fit doors; enemy HP bar height uses it too. `unstick` kicks in after 2 s stuck.
- Arrows leave from the bow (`bowPoint`: raises the bow arm, reads the bow's world position) for tower/castle archers and raider archers.
- Construction: `addScaffold` builds poles every ~1 m, plank decks per lift, braces, a ladder and material stacks; walls/torches/flowers get a light version (`LIGHT_SCAFFOLD`). Builders kick up dust (`dustAt`, shares the smoke `puffs`).
- Walls are not flattened and have no AO plane; their posts/blocks run 0.3–0.6 m below ground so runs follow slopes cleanly.
- Doors and facing: `DOOR[type][tier]` is each model's door in its own frame (front = +z). Every building except walls, gates and paths can face any side (`FACING`, `B.face` 0–3 = +z/+x/−z/−x, `faceRot`/`unrot`): `placeFace` is set with Rotate / R while placing (ghost turns with it); smart rotate: if that facing's door tile is blocked, `evaluate` picks the nearest turn whose door is open (order +0, −1, +1, +2 quarter turns; result in `ev.face`, used by the ghost and `place`), and the card's Rotate turns a placed one to the next side whose door tile is open (`doorOk`), else "Door blocked". `evaluate` rejects a spot whose door tile is blocked. Posts (`postOffset`) and farm obstacles (`farmBlocked`) follow the face. `doorCell` lines the door tile up with the door (1×1 and 3×3 on the centre, 2×2 tier-1 doors at local x −1). A door may sit off the tile's centre line (lumber shack T1 at x −0.65, the hut nearer the middle; lumber camp T2/T3 laid out like the shack: the cabin where the shack's hut stands (`LODGE_AT` −.55, −.15), drawn at `LODGE_K` .7 in x/z and `LODGE_KY` .8 in height, its door full size on the shack's door line (`LODGE_DOOR` x −.65, z .66), window right of it; log pile front right (T3 four high), chopping stump back right (1.15, −1.35); T2 a staked stack of chopped firewood on the cabin's right, T3 the sawbuck there): `doorShift` (measured from the tile's centre, 1 m off a 2×2's middle) moves the door point and the path tile's arm into the building across to it. No paths are laid automatically: the player builds them. Villagers walk from the door tile straight to `innerDoor(B)` and only vanish there (`goIn`/`exitDoor`/`doorStep`, `v.doorWalk` pauses their logic); loads are dropped once inside (`dropLoad`).
- Opening doors: `leaf(w, h, t, m, hx, y, z, dir, open)` builds a door leaf hung on a hinge (`userData.leaf` = swing angle). The castle (T1 hall door swings out over a dark doorway; T2/T3 double gatehouse doors swing in) and gates (two leaves, closed across the opening, swing out) open while a visible villager is within 1.7 m of the door (`updateDoors`: castle at `innerDoor`, gate at its centre; `B.doorK` eases open 6/s, shut 2.5/s). Raiders never open them.
- Archers draw with both hands at the bow for `DRAW` (.45 s) before each shot (`bowPose`: draw / loose / idle), town and raider alike. Melee raiders run (×1.6, faster stride, lean) within 6 m of their target.
- Movement: `steer` tries straight, then the committed side, then the other side (`STEER_L`/`STEER_R`), each group first wanting clear ground 0.65 m ahead, so units slide along obstacles instead of bouncing between sides; they face the smoothed travel direction (`v.hx/hz`). `clearLine` shortcuts need 0.22 m clearance either side. `walkTo` tracks progress (`trackProgress` → `v.noProg`, seconds without getting 0.25 m closer; `unstick` resets `v.stuck` every 2 s, so give-ups must use `noProg`) and counts a crowded spot as reached (within stop + 0.7 m after 0.8 s without progress). Builders each take their own `workSpot` just outside the site (0.6 m out, 0.8 m from other builders' spots), switching spots after 5 s without progress. `separateUnits` weights pushes: walkers 1, standing .35, working .1, so walkers step round people standing still.
- Work strokes (`stroke(p)`): slow eased wind-up (w 0 → −1), fast strike (→ +1), short hold at impact, recovery; the hit (w passing +0.85) plays the sound and throws chips (`chipBurst`/`updateChips`, `CHIP`: wood, stone, clods, splinters). Axe 1.1 s with a body twist into the trunk (`twist` → `body.rotation.y`), landing at chest height; pick 1.25 s; hoe 1.05 s (the recovery drags the blade back); hammer 1.9 s = three light taps and a big blow, half the builders kneeling (by seed).
- Pick and hoe work low: `TOOL_POSE` returns a `crouch` (0–1) applied with `kneel()`; the mason drops onto a knee as the pick comes down, the farmer stays crouched and dips with each stroke. Never use a big forward `lean` for a stoop: the figure only pivots at the ground.
- Villager poses ease toward their target (arms, tool tilt, lean at 14/s) and tool swings are timed from a fixed per-villager `v.seed`, never `v.phase` (the stride keeps advancing `phase` while it fades out, which made the first strokes run 10× fast).
- No jitter: villagers and raiders are drawn at an eased position (`smoothPos`: `rx/rz` follow `x/z` at 10/s, snap after a >2.5 m jump or 200 ms unseen) and their stride fades in/out (`stride`, `amp`); a blocked `steer` still counts as walking, so stuck units stride in place instead of twitching.
- Fire: torch flames are unit cones (`FLAME_GEO`) in three unlit, see-through layers (`M.flame` orange, `M.flameMid`, `M.flameCore`) animated by `flameShader` (sway, lick, stretch; phase from each tongue's position, time from `windU`); flame meshes set `userData.noShadow`. Torches shed embers (additive sprites in `puffs`, `ember: true`). The gallery advances `windU` itself.
- Well: stone apron, rubble ring with a coping, windlass (axle, wound rope `ropeM`, crank) on two posts, bucket hanging on its line, gable tile roof, spare bucket. Quarry T2 back yard: mason's bench with a half-dressed block, rubble heap, wheelbarrow. Castle T3 gatehouse has merlons. Masons' yard (quarry T3): the hoist stands on the yard's right with its block over a cart being loaded. Chimney smoke follows the building's facing.
- Castle T2/T3 are drawn narrower in x/z (`CASTLE_K` .9/.82, posts scaled too) so corner towers stay inside the 3×3 plinth.
- Castle T2 is all warm stone (`M.stone2`, like T3): plain curtain walls, square corner towers open on top, keep with a straw roof. Castle T3 holds 5 archers (2 on the keep, 1 on each wall-walk except the gate side).
- Houses stay plain and ordinary so they never outshine the castle: T1 hovel, T2 daub cottage with corner posts and a straw gable roof, T3 one tall stone storey with a timber band, plaster gable and blue gable roof (no upper floor). All three are ~1.3–1.45 m to the eaves so the standard door fits. One door, few windows, small chimney.
- Doors: every tier-1 building's door, every house door and every barracks door is the lumber camp's size, `DOOR_W` .55 × `DOOR_H` 1.0 (bottom on the slab/plinth top); buildings were raised to fit (hovel, cottage, townhouse, lumber shack (4 log courses), stone pit shed, muster hut, barracks hall, farm T1 hut, farm T3 barn, which got a door). The palisade fort's hall door is .72 × 1.16 (windows above it at y 1.98); the stone keep's own door (inside the courtyard) is the standard door, `DOOR_W / k` wide so it stays .55 m after `CASTLE_K`. The hovel has no fence posts beside it.

## Maps
- Three maps, picked on a dark title screen ("Medieval Town Defense", "Choose map"; `#mapPick` covers everything, visible from the first paint so the game never shows behind it) on entry and on Restart / Play again (`#mapPick`, `showMapPick`; each card shows a picture of the real map, `maps/meadow.jpg` / `maps/isle.jpg` / `maps/pass.jpg`, rendered by `node tools/render/maps.js [--three …]` (re-run after changing a map); the game waits paused underneath; last choice in `localStorage['mtd-map']`, highlighted). `?map=meadow|isle|pass` (and `?debug` / `?gallery`) skip the picker; a stored choice that isn't a known map is ignored. `MAP` is read by `genHeight`, `genTrees`, `genRocks`, `canStand`; `KX/KZ` (castle site) are set per map in `startGame` (Meadow 19,27 / cells 8–10,12–14; River isle 27,27 / cells 12–14,12–14; Mountain pass 37,21 / cells 17–19,9–11).
- **Meadow**: the original map: a winding river on the east side (`meadowRiverX`), crossed by one fixed bridge square across it on the castle's row (`bridgeRays`). Rocks: a stony patch between the castle and the river north of the bridge (8) plus up to 48 scattered (≈510 stone). Nobody wades any river (`canStand` modes 1 and 2 need h ≥ .3), so raiders spawning east of it must cross the bridge.
- **River isle**: the castle on a flat island inside a wobbly ring of river (`ISLE.r` 16.6 m, `isleR(angle)`), hills beyond the far bank. Two more rivers flow out of the ring to the map's edge, north-east and south-west (`isleOutN`/`isleOutS`, carved in `genHeight` outside the ring only), so the far bank is split in two. Three fixed, free timber footbridges at `ISLE_BRIDGES` (−90°, 30°, 150°), each radial (square across the ring). Bridges at any angle (`genBridges` from `bridgeRays`: march along a ray; each end runs on past the water until it lands on flat ground at the bank top (`flat`: height > .5, slope < .6 on the centre line and 1.3 m either side, up to 6 m), so the deck is level with the ground beside its ends; trestles wherever the deck is over 1 m above the ground; a bridge is `x0, z0, dx, dz, L`, deck `DECK_W` 1.9; `bridgeT`/`bridgeW`/`onDeck`; `bridgeCell[n]` = index + 1 for every cell the deck touches, `b.ends` its end cells). `deckY(b, t)` arches the deck (`BRIDGE_RISE` .45); units stand at `walkY` (the deck inside its strip, else the ground) everywhere they are drawn; `cellPass` lets everyone path over bridge cells, `canStand` only on the deck strip; A* steps on and off a bridge only through its end cells; `routePoints` turns a run of bridge cells into: a point on the ground 0.8 m in front of the entry end, the deck's end, its far end, the ground beyond (on-deck starts/targets keep `bridgeWaypoint` centre-line points); a unit standing on the ground in a cell a deck touches counts as off the bridge (`deckAt`, in `findPath` and `clearLine`), else it was routed up the deck's side and stood stuck on the bank; raiders can't wade (`canStand` mode 2 needs h ≥ .3). Nothing can be built or pathed on a bridge ("Bridge"). Model: `makeBridge` (planks across the arch, two log stringers, trestles where it crosses water, log railings, grey stone landings), `buildBridges` after `syncTerrain`. Woods on the island (clear round the castle and along the way to each bridge), forest beyond the river; stone only beyond the river: three outcrops between the bridges (`ISLE_ROCKS`, `isleRockSite`, 7 rocks each) plus 16 scattered rocks, so masons either live by the castle and walk via a bridge or build out by the rocks, exposed.
- **Mountain pass** (`MAP` 'pass'): no water. The castle on a plateau at the top right (`PASS.plate` 9.5 m round it, height 6); the open ground (the pass) sweeps down from it to the open stretches of the left and bottom edges (about 1 m at the bottom-left corner, rolling a little), bounded by Jack's uneven line of mountains along the top-left, top and right (`PASS_EDGE` polyline, `PASS_POLY` closes it round the bottom-left corner; `passAt` gives the depth inside it, wobbled by noise so it isn't symmetrical); rough mountains beyond (8–18 m, ridged noise, snow over 16 m via `SNOW_C` in `recolor`) behind 3 m cliffs (`passHeight`). `passOpen(x, z)` (depth > .3) is the only ground anyone may stand on, path through or build on (`canStand`, `cellPass`, `evaluate` "Too steep"), so every raider comes up the open ground from the left and bottom edges, where they spawn (`edgePoint`). Trees: a forest ring round the castle except toward the south-west, trees along the foot of the mountains, clumps in the open, and unreachable `deco` pines on the mountains (`treeFree` skips them). Stone is plentiful: outcrops at `PASS_ROCKS` (seven, 8 rocks each) plus 14 scattered (~70 rocks). Rules (`MAP_RULES.pass`, applied by `mapRules()` in `startGame`): one 600 s day, then night 1 = 70 raiders (36 spear, 18 sword, 14 archer, 2 captains, hp ×1.2), a 150 s day, night 2 = 100 (46/28/22 + 4 captains, hp ×1.45); raiders spawn every `SPAWN_GAP` .5 s; same starting resources. The camera starts looking up the pass (`yaw` −.72). Only a raider's bigger parts (bounding radius ≥ .16) cast shadows (`spawnEnemy`), as up to 100 can be on screen.
- Raiders route on the cell grid with `walkTo` (mode 2) toward a fixed point on their target's near side (`e.tp`, reset on each 3 s retarget), straight `steer` only within 3 m; a wall in the way (stuck or 3.5 s without progress) is attacked as before. Spawn points (`edgePoint`) must be walkable (`cellPass` mode 2) and have a route to the castle's door (a route to the castle's centre never exists: it is inside the building), else raiders spawned on steep edge hills stood stuck.
- No building over a rock (`evaluate`: "Rocks"), so stone is never buried.
- **Map sides** (`buildEdges`, from `syncTerrain`): solid earth walls from the ground's edge down to `EDGE_BASE` −4 (vertex-coloured: grassy lip, soil, darker below) and a water cross-section where a river runs off the edge, so the map reads as a block of land from low angles. (A 50 m scenery skirt beyond the map was tried and dropped.)
- Ledges: bridges are entered and left only at their ends, along the deck (`findPath` refuses moves onto or off a bridge except through its end cells); `steer`, `clearLine` and `separateUnits` refuse a move that changes `walkY` by more than a step's worth (≈.2–.35 m), so nobody hops up onto a deck from the side. `clearLine` shortcuts may touch a bridge cell only when both ends are on that bridge, so the path's waypoint lined up with the bridge's end is never skipped (raiders used to cut in from the side and stall on the bank below the deck). A raider held up in a crowd (another raider within 1.3 m, e.g. queueing for a bridge) waits instead of taking the random 5 m detour, which scattered queues onto the riverbank.
- Progress for give-ups is measured along the planned path (`pathLeft` in `trackProgress`), so a detour (round to a bridge) isn't mistaken for being stuck.
- **Arrow volley** (castle card, button left of Rotate: three falling arrows; `#volleyBtn`): tap it ("Tap a spot"), then tap anywhere on the map (`volleyAim`, handled first in `tap`; a mouse previews the circle on hover): `castVolley` shares the arrows among the castle's manned archers (`volleyFigs`; nobody posted: from the castle top), who turn to the spot, draw high and shoot upward (`volleyPose`, set in `updateVolley` after `updateDefense` while `C.volley` lasts; each arrow leaves from its archer's bow) over ~1 s (`volleyQ`), high arcs (`fireArrow`'s `arc`) to random points in a circle round the tapped spot (blue `volleyLine` ring, dust where each lands); every enemy inside the circle takes the volley's damage, shared over the arrows as they land. By castle tier (`VOLLEY`): arrows 12/18/26, radius 2.2/3/3.8 m (`volleyR()` for the hover preview), damage 45/65/90. Cooldown `VOLLEY.cd` 20 s of game time (`volleyCd`; the button dims and shows the seconds left). Night only: by day the button is dimmed (`.off`) and a tap says "Night only"; aiming is cancelled at dawn. Reset in `startGame`.
- Selecting a castle or archer tower draws its archers' range (`rangeLine`, `syncRange` from `refreshCard`).

## Gameplay summary
- 28×28 grid of 2 m cells. Start: castle prebuilt in the middle, 3 villagers, gold 40, wood 45, stone 0, food 20.
- **Day/night**: 5 waves on Meadow and River isle (`WAVES_STD`; `WAVES`, `NIGHTS`, `DAYLEN`, `SPAWN_GAP` are set per map by `mapRules()`; Mountain pass has 2). Day 1 lasts 300 s, days 2–5 last 150 s (`DAYLEN`); the last `DUSK` 40 s fade slowly to night (light and dusk colours in `updateLight`), with a "Dusk · Night N soon" banner and log line as it starts. Nothing is earned at night: no payouts (the `econT` ring waits for dawn) and a load carried in after dark is lost (`deliver`). Night ends when all enemies are dead. Summary screen at the end.
- **Waves** (`WAVES`): spearmen are the basic raider and come first. 1 = 7 spears + 2 archers; 2 = 9/4 swords/3 archers (hp ×1.15); 3 = 10/6/5 + captain (×1.3); 4 = 12/9/7 + captain (×1.45); 5 = 14/12/10 + 2 captains (×1.6). Targets (`pickTarget`): spearmen the nearest building; swordsmen the nearest archer tower (else nearest building); the mounted captain the castle; archers the nearest non-wall building, shooting over walls (`lob` adds 3.5 m reach when a wall blocks them).
- **Economy**: payouts every `TICK=20` s (ring in top panel). Each villager eats 1 food every `MEAL=20` s of daylight; hungry villagers go home and sleep. A farmer who goes hungry leaves the field (`v.job = null` in `feedVillager`); `assignJobs` (also every 0.5 s by day) fills farms first and, while food is low (`foodLow`: under 3 meals a head, or `foodMade()`, the farms' (by farmers at work) and castle's food per payout, is less than the villagers eat per payout), moves a lumberjack or mason (not carrying, building or posted) to an empty farm job ("Food low · worker to the farm", at most every 20 s).
- **Barracks soldiers**: at nightfall `assignPosts` fills posts in priority order (castle, then archer towers, then barracks; `rank`) with whoever is free; a barracks takes up to 3 and may go short. A villager carrying a log or stone delivers it on posting. The villager walks to its door, goes in, changes for ~1.4 s (`v.kitT`), comes out geared (`soldierKit`: T1 Militia blue tunic + padded cap + spear; T2 Guard leather jerkin + kettle hat + spear + round wooden shield; T3 Man-at-arms mail + blue surcoat + steel helm + sword + blue kite shield) and stays out (`v.soldier`, `updateSoldier`): holds the door or the rally flag (`SQUAD` offsets), engages raiders within 6 m of that spot, drops ones 9 m away or unreachable (4 s without progress). Melee raiders fight any soldier within 2.2 m (horse 2.6) before their building target (`nearestSoldier`, `hurtSoldier`). A fallen soldier falls over (`fallen`), leaves the town and is queued in `respawns`; after 60 s of daylight a villager returns to that home (or the castle); `syncResidents` counts pending respawns. At dawn soldiers walk back to their barracks, go in, change (`v.unkit`, `updateUnkit`, `stripKit`) and come out to their day's work (a lost barracks: they change where they stand); dawn while still changing sends them out unarmed. Spears (raider spearmen, Militia, Guard) are held level at the hip pointing forward; a strike lasts `SPEAR_T` (.5 s) in three beats: draw back, drive out 0.45 m with a small lunge (body steps .15 m and leans .12), recover (`spearPose`/`spearThrust`: arm + tool tilt + lean stay at −1.57 so the shaft stays level; the grip slides down the shaft). Swords (raider swordsman and captain, Man-at-arms) cut over `SWORD_T` (.5 s, `swordPose`): raise overhead with the wrist cocked back, chop down to low in front with a .1 m step-in, recover. Soldier strikes are set exactly after the pose easing (eased, they go soft). Shields are worn on the outside of the left forearm (`armShield`): `roundShield` (wood, iron boss and rim: Guard, raider swordsman) and `heaterShield` (flat top, pointed foot, rimmed: Man-at-arms blue `kiteM` with steel rim, raider captain black with a pale rim); raider spearmen carry none, raider archers wear a pointed iron cap over a dark coif. Blue cloth that must not wave uses `kiteM`, never `M.flag` (it has the flag-wave shader). Barracks T2/T3 fly a flag on the roof peak. Rally: barracks card → Rally, then tap the ground (`rallyFor`, `setRally`, blue flag); Recall clears it. A destroyed barracks keeps its soldiers.
- **Changing clothes**: only soldiers go indoors to change (barracks, above). Everyone else changes on the spot: whenever the clothes for the next task (`toolFor`: builder hammer, job tool, or plain) differ from what a villager wears (`v.toolKind`), `updateChange` stops them for `CHANGE_T` (1.1 s), they kneel (`kneel(p, c)`: body down, one knee forward, hands to the ground; the figure bends only at the ground, so a stoop tips it over like a plank) and the outfit and tool swap at the bottom; indoors it just happens. Jobs never go to anyone in soldier's kit (`assignJobs` skips `v.soldier`/`v.unkit`).
- **Villagers**: live in houses/castle, take jobs, commute, walk to construction sites and build them before they work (`assignBuilders` every 0.5 s). At night they man the castle (priority) and towers; the rest hide in the castle.
- **Decor charm** boosts house gold within `CHARM_R=8`. Paths add `PATH_CHARM=.02` each (path bonus capped at +20%). Paths make everyone (including raiders) move ×1.6.

## Technical notes
- **Colour**: `THREE.Color` setHex/setStyle/setHSL patched to convert sRGB→linear; renderer uses sRGBEncoding + ACES filmic, exposure 1.1. Overlays use `toneMapped:false`.
- **Terrain**: heightmap, 1 m vertex spacing (V=57). Placing a building snaps to cells, checks slope, flattens with smoothstep falloff, locks the footprint, lays a dirt splat, adds a plinth and clears trees. "Adapt terrain" is always on.
- **Auto-tiling**: bitmask N=1 E=2 S=4 W=8 for paths and walls/gates (`wallMask`, `refreshWalls`, `swapModel`).
- **Wall/gate rotation**: `B.rot` (0 = E–W, 1 = N–S) from `placeRot` (Rotate button in the dock / R while the wall or gate tool is active; ghosts rebuilt via `makeGhost`). A lone wall (mask 0) is a straight run along `rot`; connected walls auto-tile as before. A gate follows walls on one axis, else `rot`; rotating from the card (`rotateBuilding`, also R with it selected) sets `rotFixed` so it keeps that direction. Passability is unchanged (gates pass villagers either way).
- **Paths**: packed-earth tracks built from overlapping discs (centre + 3 per connected arm, radius wobbling by world position so neighbours agree): darker base layer for the worn edge, smooth position-based colour on top, and flat set stones (`pathStones` InstancedMesh; `frustumCulled=false` and `instanceColor` pre-sized, both needed in r128).
- **Pathfinding**: A* on cells (`findPath`, `cellPass`, `walkTo`), `clearLine` line-of-sight shortcuts, `unstick` after 3.5 s without progress, cache invalidated on any build/path change. `steer`/`turnTo` commit to one side round obstacles. Villagers enter/exit buildings via their door.
- **Villager states**: wander, visit, commute, find, go, work, home, drop, building, hungry/sleeping, night posts.
- **Shaders (`onBeforeCompile`)**: tree wind sway, procedural ground detail, masonry (running-bond + mortar) on `M.stone`/`M.stone2`, flag wave anchored on position x, hanging banners (`M.drape`) anchored at the top. `tinted()` copies `onBeforeCompile` onto clones.
- **Stone bases**: every plinth fills its footprint exactly (2 m per tile), so neighbours meet edge to edge. `snapToNeighbours` (called from `evaluate`) sets a new stone-based building's target height so its plinth top (`PLINTH_TOP`) is flush with an edge-sharing neighbour's, if within 0.8 m; the masonry shader is world-space, so joints run straight across.
- **Farm obstacles**: `FARM_OBST` per tier (hut, hay, scarecrow, barn, stooks); `canStand` rejects them although farms are walkable, and `cellPass` refuses a farm cell whose centre is an obstacle, so A* routes round the hut instead of aiming through it (units still walk the open ground beside it).
- Doors: `nearDoor` counts a unit held up within 1.6 m of the door point (never just near the building), and `goIn` walks in through the door only from within 1.7 m of it; a give-up further off just goes inside unseen. (Villagers stuck behind a house used to walk through its walls to the door inside.)
- **Tree cutaway**: `cutaway(sh)` on trunk/crown materials dither-discards trees near the camera→`target` sightline (shadows unaffected).
- **Instancing**: trees (instanceColor), clutter (320 tufts, pebbles, bushes) hidden when any part of it (radius by kind, centre + 8 points round it) reaches an occupied, path or bridge cell (`seatClutter`; bushes beside a base used to poke onto it). Lone trees within 12 m of the castle, forest 12–18 m.
- **Water**: one plane at y 0 (`waterMat`, roughness .7 and no metalness: shinier water glared white toward the sun at low angles); its shader (`flowing-water` cache key) drifts two layers of noise with the current (down the Meadow's river along z, round the isle's ring about `KX/KZ`, `waterU`) for light streaks and darker patches, and lays broken foam where the bed is shallow (bed height from `hTex`, a byte texture of the heightmap refreshed in `syncTerrain` via `syncWaterTex`). Tiny splashes: `genShore` lists shoreline points (h −.12….02, not under bridges) and `updateSplashes` pops 3–5 white droplets (`splashM`, shared `chips` list) at a random one every .12 s. Spray: every .06 s three soft mist sprites (`sprayAt`, `spray: true` in `puffs`) rise from a shoreline point and drift with the current (`flowVel`, matching the shader), dimmer at night.
- **Lights**: pool of 4 PointLights shared by night lamps; gradient sky dome.
- **Sprites**: HP/progress bars (`fg.center.x=.5/f` trick); floating SVG icon pop-ups for income (`floatRes`; `ICON_IMG` holds gold, food, wood and stone, any other kind has no picture).
- **People**: `makePerson` → arms on pivots (angle 0 = hanging, −1.57 = forward, −3 = overhead). Tools come from `makeTool(kind)` and are parented to the hand (`arms[1]`; bow on `arms[0]`); `giveTool(v,kind)`. Task poses are all one-handed (the single-segment arms can't both reach one handle; the free arm steadies): axe overhead chop, pick overhead strike, hoe bent low, hammer; log on right shoulder with the hand resting on it, stone held at chest in both hands. Axe and hoe heads sit on the local −z side so they lead the swing / face the soil. Bow is a gentle C (arc segments). Colour code: plain villagers wear browns (`tunics`), workers yellows (job outfits), soldiers blue (`guardTunic`), every raider the same red (`raiderRed`); the town's flags (`M.flag`) are blue. Everyone has short hair (`makeHair`, `hairs` palette); some plain villagers add a soft cloth cap. Headgear via `makeHelm`: villager archers on posts a bright steel round helm with a blue band and nose guard (`soldier`; `kettle` also exists), raider iron dome with nose and cheek guards, captain adds a red crest, raider archer a dark rounded hood. Outfits via `OUTFIT`/`dress()`: lumberjack yellow/brown checked shirt (`plaidMat` canvas texture) + green wool cap with feather, mason khaki + grey cloth bonnet + curved canvas apron with a leather waist band, farmer straw yellow + straw hat, builder amber smock + brown felt hat + tool belt. Renders of all of them: `design/characters/`.
- **Ambient**: bird flocks every 45–95 s (scale 0.55, half circle), waving flags.

## Audio
- Event → file map in `SND` (effects, decoded) and `LOOPS` (theme music and birdsong, streamed through `<audio>` + MediaElementSource). File names are the owner's (e.g. `Woodcutter_axe.mp3`); see `audio/*/README.md`.
- Levelling as in medieval-td: each decoded clip gets gain = `TARGET_LOUD` (0.09) × trim ÷ RMS of its loudest 0.3 s, clamped to [0.1, 6] and to a peak ceiling of 0.95 at the output (`MASTER` 0.9). Trims follow medieval-td where the sounds match (click/attack .445, arrow .889, sold .7, hammer .668, axe .736).
- `strikes: true` clips (axe, pick, hammer, hoe) are long recordings; `strikes()` cuts single strikes at onsets (10 ms envelope > 25% of peak after 80 ms quiet), each levelled on its own; one random cut plays per tool impact (swing sine passing +0.85).
- Loops can't be measured at load; their `vol` was measured offline (theme 0.254, birds 0.214 loudest-0.3 s RMS) to sit ~6 dB / ~10 dB under effects. Re-measure if the files change.
- `Medieval_theme_music` loops by day (with birds), `Night_theme_music` at night (falls back to the day theme if missing); `Victory_sound`/`Defeat_sound` stop the loops and play once. `attack` (two takes, never the same twice) on raider melee strikes. Nightfall plays `Wave_horn` and switches to the night theme. No file yet for upgrade or raider-hit; those events are silent.
- Audio starts on the first tap/key (`unlockAudio` on pointerdown, pointerup, touchend, click and keydown, retrying until the context runs and the wanted loops play: phones only count a finger lifting as a gesture; `navigator.audioSession.type = 'playback'` so iOS plays sound with the silent switch on). Mute (`#muteBtn`, key M) persists in localStorage; audio pauses when the tab is hidden. Audio state uses `var` because `sfx()`/`setMusic()` run during the startup reset.

## Gotchas fixed before (don't reintroduce)
- `var paused` (not `let`) — TDZ crash on startup.
- `crowns.instanceColor` is pre-sized to `MAXT`: r128 sizes it from `.count` at the first `setColorAt`, so switching to a map with more trees showed garbage crown colours.
- Global `[hidden]{display:none!important}` — otherwise flex modals ignore `hidden`.
- Restart confirm needs `resetArmed && ...` guard.
- Flag waves must anchor on position, not uv (uv tore between box faces).
- `randomNear` targets must not land inside a building footprint (villagers stalled at the castle gate).
- `evaluate` rejects solid buildings on another building's door cell (villagers exiting got snapped back into a blocked door forever). Flowers/torch/gate are still allowed.
- The file must keep `<!doctype html>`, `<meta charset>` and the viewport meta (the claude.ai artifact wrapper used to add them; without them phones render zoomed-out and arrows show as mojibake).
